Задание 3. Атака Ферма — диалог с AI

--- Запрос 1 ---
Я: Объясни метод факторизации Ферма для RSA, когда p и q близки. Напиши псевдокод или
Python-функцию, которая находит p и q по N.

AI: Метод основан на представлении N = A^2 - B^2 = (A-B)(A+B), где A = (p+q)/2, B = (p-q)/2.
Если p и q близки, A будет очень близко к sqrt(N). Алгоритм:
  1. A = ceil(sqrt(N))
  2. Вычислить B^2 = A^2 - N
  3. Если B^2 — полный квадрат, то p = A + sqrt(B^2), q = A - sqrt(B^2)
  4. Иначе A += 1, повторить.

Псевдокод:
  A = isqrt(N); if A*A < N: A += 1
  while not is_square(A*A - N): A += 1
  B = isqrt(A*A - N)
  p, q = A+B, A-B

Комментарий: разобрался, почему это работает — если p и q близки к sqrt(N),
поиск A рядом со sqrt(N) сходится быстро, т.к. количество итераций ~ (p-q)^2/(8*sqrt(N)).

--- Запрос 2 ---
Я: Напиши полный скрипт на Python, который получает N и e из файла crypto.py, факторизует N
методом Ферма, вычисляет d, расшифровывает ciphertext.txt (число) и выводит флаг в читаемом виде.

AI: [сгенерирован скрипт fermat_attack.py — итеративный Ферма с инкрементальным пересчётом
A^2 через (A+1)^2 = A^2 + 2A+1 вместо полного возведения в квадрат на каждой итерации,
и gmpy2.is_square() для быстрой проверки квадрата вместо iroot на каждом шаге.]

--- Запрос 3 (отладка) ---
Я: Первый прогон не сошёлся за 90 секунд / 348 млн итераций — атака Ферма не сработала?
Почему метод Ферма мог не сработать? Какие ещё атаки можно применить для близких p и q?

AI: Скорее всего дело не в самом методе, а в исходных данных — при копировании длинного
десятичного N из терминала (перенос строки в выводе cat) легко потерять/сместить цифры.
Стоит проверить: (1) длину N в битах — для 2048-битного RSA N должен быть ~2048 бит,
(2) собрать N заново, точно склеив все строки без пробелов и переносов.
Если N собран верно, а p и q всё равно далеко — тогда действительно нужны другие подходы:
атака Полларда (p-1), ро-метод Полларда, или факторизация через ECM.

Я перепроверил и обнаружил ошибку копирования: N был неверно склеен из-за переноса строки
в выводе терминала (потерялись/сдвинулись цифры на стыке строк). После точной склейки трёх
фрагментов N оказался 1024-битным (а не ~566 бит, как получилось из повреждённой копии) —
это и есть корректный модуль для данного задания.

Я: Правильный N восстановлен. Повторный прогон Ферма?

AI: Замени переменную n в скрипте на корректно склеенное значение и запусти заново — с
правильным N (p и q реально близки) метод Ферма должен сойтись за секунды/десятки секунд.

--- Результат ---
С исправленным N атака Ферма сошлась за ~17 секунд (~60.6 млн итераций).
p и q отличаются лишь в последних нескольких десятках цифр — подтверждает, что числа
были сгенерированы намеренно близко друг к другу.

d = e^-1 mod phi(N) вычислен через gmpy2.invert.
Расшифровка: flag = pow(c, d, n) -> bytes -> UTF-8.

Флаг: S21{h3y_dud3_1_r34lly_l1k3_70_l1v3_50_cl053_70_y0u}

Итог: логику атаки понял и объяснил сам (A/B из среднего и полуразности p,q, критерий
сходимости через квадрат разности), скрипт написан с помощью AI, но финальную проверку
результата (факторизация p*q==n, корректность расшифровки) выполнил самостоятельно.
